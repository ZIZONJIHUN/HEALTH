# 근육 세분화 + 3D 인체도 확대/축소 구현 계획

작성일: 2026-08-29
선행: `docs/superpowers/specs/2026-08-08-taste-ui-redesign-design.md`

## 목표

1. 부위를 7개 → **18개 + 전신**으로 세분화한다
2. 칩은 **2단계 펼침**으로 보여준다 (상위 7개 → 누르면 세부 칩 한 줄 추가)
3. 3D 인체도에서 **세부 근육 단위로** 잡히게 한다
4. 3D 인체도를 **마우스 휠(PC) / 두 손가락(모바일)** 로 확대·축소한다

## 하지 않는 것

- 상위 7개 부위의 id·라벨·검색어는 **바꾸지 않는다.** 기존 사용법과 E2E 를 그대로 둔다
- 근육 단위(외측광근, 내측광근 …)까지는 안 간다. `외측광근 운동` 같은 검색어는 YouTube
  결과가 거의 없어 빈 화면만 늘어난다
- 세분화 검색어를 사용자가 직접 편집하는 기능

## 1. 세분화 표 (18개)

검색어는 **해부학 용어가 아니라 헬스장에서 실제로 검색하는 말**로 잡는다.
`대흉근 쇄골지 운동` 보다 `윗가슴 운동` 이 결과가 훨씬 많다.

| 상위 | 세부 id | 라벨 | 검색어 | 모델에 넣을 근육 |
|---|---|---|---|---|
| 가슴 | `chest-upper` | 윗가슴 | 윗가슴 운동 | 대흉근 쇄골지 |
| 가슴 | `chest-lower` | 아랫가슴 | 아랫가슴 운동 | 대흉근 흉늑지·복부지 |
| 등 | `back-lats` | 광배근 | 광배근 운동 | 광배근 |
| 등 | `back-traps` | 승모근 | 승모근 운동 | 승모근 상·중·하부 |
| 등 | `back-erectors` | 기립근 | 기립근 운동 | **신규** 장늑근·최장근·극근 |
| 어깨 | `shoulder-front` | 앞어깨 | 전면 삼각근 운동 | 삼각근 쇄골부 |
| 어깨 | `shoulder-side` | 옆어깨 | 측면 삼각근 운동 | 삼각근 견봉부 |
| 어깨 | `shoulder-rear` | 뒤어깨 | 후면 삼각근 운동 | 삼각근 극부 + 극하근 + 대원근 |
| 팔 | `arms-biceps` | 이두 | 이두 운동 | 상완이두 + **신규** 상완근 |
| 팔 | `arms-triceps` | 삼두 | 삼두 운동 | 상완삼두 + 주근 |
| 팔 | `arms-forearm` | 전완 | 전완근 운동 | 전완근 9종 |
| 코어 | `core-abs` | 복근 | 복근 운동 | 복직근 |
| 코어 | `core-obliques` | 옆구리 | 옆구리 운동 | 외복사근 + 전거근 |
| 하체 | `legs-quads` | 허벅지 앞 | 대퇴사두 운동 | 대퇴사두 4종 + 봉공근 + 대퇴근막장근 |
| 하체 | `legs-hamstrings` | 허벅지 뒤 | 햄스트링 운동 | 대퇴이두 + 반건양근 + 반막양근 |
| 하체 | `legs-glutes` | 엉덩이 | 엉덩이 운동 | 대둔근 + 중둔근 |
| 하체 | `legs-calves` | 종아리 | 종아리 운동 | 비복근 + 가자미근 + 전경골근 + 장비골근 |
| 하체 | `legs-adductors` | 허벅지 안쪽 | 내전근 운동 | 내전근 3종 + 박근 + 치골근 |

`전신`은 세분화가 없다. 상위 칩만 있다.

**극하근·대원근을 '등'이 아니라 '뒤어깨'에 넣는 이유**: 위치상 후면 삼각근 바로 아래에
붙어 있어서, 등으로 묶으면 3D 인체도에서 어깨를 눌렀는데 등이 켜지는 것처럼 보인다.
훈련상으로도 후면 어깨 루틴에서 같이 쓴다.

## 2. 작업 순서

### 2-1. 데이터 구조 (`src/data/categories.ts`)

```ts
export const BODY_PARTS = [...]                       // 그대로 둔다
export const MUSCLE_GROUPS = [
  { id: 'chest-upper', parent: 'chest', label: '윗가슴', query: '윗가슴 운동' },
  ...
] as const
```

- `parent` 는 `BODY_PARTS.id` 를 가리킨다
- 조회용 헬퍼: `subgroupsOf(parentId)`, `findByQuery(q)` (칩 활성 표시와 3D 하이라이트가 공유)

### 2-2. 모델 재빌드 (`scripts/build-body-model.mjs`)

지금은 노드가 상위 7개다. **노드를 세분화 18개로 바꾼다.** 노드 이름 = `MUSCLE_GROUPS.id`.

- 신규 근육: 기립근(장늑근 요·흉부, 최장근 흉부, 극근 흉부) 8개, 상완근 2개 → 총 113개 메시
- 삼각형 예산을 세분화 단위로 다시 나눈다 (합계 약 7만 유지)
- **노드 이름 목록을 `src/data/bodyModelNodes.json` 으로 함께 내보낸다** ← 아래 2-6 참고

### 2-3. 칩 2단계 (`CategoryChips`)

```
[가슴] [등●] [어깨] [하체] [팔] [코어] [전신]
  └─ [등 전체] [광배근] [승모근] [기립근]
```

- 펼침 상태는 **URL 의 `q` 에서 유도한다.** 컴포넌트 상태로 들지 않는다 —
  뒤로가기와 공유가 그대로 동작해야 한다
  - `q` 가 세부 검색어와 일치 → 그 부모를 펼치고 그 세부를 활성 표시
  - `q` 가 상위 검색어와 일치 → 그 부모를 펼치고 `전체` 를 활성 표시
  - 둘 다 아니면(예: `스쿼트`) 접는다
- 상위 칩을 누르면 **지금처럼 검색도 되고**, 세부 줄이 함께 열린다. 기존 사용법 보존
- 세부 줄 첫 칩은 `<상위> 전체` — 세부에서 상위로 돌아갈 길

### 2-4. 3D 인체도 세분 선택 (`BodyModelPicker`)

- 노드 이름 → `MUSCLE_GROUPS` 조회로 바꾼다
- hover 캡션에 세부 라벨 (`햄스트링`)
- 클릭 → 세부 검색어로 이동
- 선택 하이라이트:
  - `q` 가 세부와 일치 → 그 노드만 라임
  - `q` 가 상위와 일치 → **그 상위의 모든 세부 노드**를 라임 (지금 동작 유지)

### 2-5. 확대/축소 (신규)

카메라 거리 `2.45` 를 상태로 만들고 `1.3 ~ 3.4` 로 제한한다. 지금처럼 감속 보간한다.

- **PC**: 캔버스 위 `wheel` → 거리 변경. `{ passive: false }` + `preventDefault()` 로
  페이지 스크롤을 막는다
- **모바일**: `touchstart/touchmove` 에서 손가락 2개일 때만 두 점 사이 거리 비율로 줌.
  `{ passive: false }` + `preventDefault()`
  - `touch-action` 은 지금의 `pan-y` 를 유지한다. 한 손가락 세로 드래그는 페이지 스크롤,
    가로 드래그는 회전, 두 손가락은 줌으로 갈린다
  - `pan-y` 상태에서는 브라우저 기본 핀치줌이 이미 꺼져 있어 우리 핸들러와 싸우지 않는다
- 확대된 상태에서만 뜨는 **초기화 버튼**을 둔다. 확대하고 길을 잃으면 돌아올 길이 없다
- 키보드 사용자는 휠·핀치를 못 쓴다. 줌은 어디까지나 부가 기능이고, 부위 선택은
  칩으로 전부 가능하다는 원칙은 그대로다

### 2-6. 모델↔데이터 정합성 테스트 (이번 계획의 핵심 안전장치)

지난번에 **모델에 근육이 없는 부위가 회색으로 비고 클릭도 안 되는** 결함이 있었다.
빌드 스크립트와 화면 코드가 각자 목록을 들고 있으면 어긋나도 아무도 모른다.
세분화하면 목록이 18개로 늘어 어긋날 여지가 훨씬 커진다.

- 빌드 스크립트가 실제로 구운 노드 이름을 `src/data/bodyModelNodes.json` 에 쓴다
- 단위 테스트로 대조한다:
  - `MUSCLE_GROUPS` 의 모든 id 가 모델 노드에 있는가 (화면에 있는데 모델에 없는 부위 = 회색 구멍)
  - 모델 노드가 전부 `MUSCLE_GROUPS` 에 있는가 (모델에 있는데 화면이 모르는 부위 = 클릭 불가)
  - 모든 `parent` 가 `BODY_PARTS` 에 있는가
  - 검색어 중복이 없는가 (중복이면 활성 표시가 두 곳에 켜진다)

### 2-7. 시드 확대 (`scripts/seed-cache.ts`)

지금은 인기 운동 20개만 시드한다. **부위 검색어는 시드하지 않아서** 첫 화면에서 가장 많이
눌리는 칩이 매번 쿼터를 쓴다. 세분화하면 19개가 더 늘어 더 심해진다.

- 시드 대상에 `BODY_PARTS` 7 + `MUSCLE_GROUPS` 18 을 더한다
- 20 + 25 = 45건 × 101 = **4,545 units** (일일 10,000 의 45%). 7일 캐시라 주 1회면 된다
- 쿼터 소진 시 즉시 멈추는 기존 동작은 그대로

## 3. 검증

| 단계 | 방법 |
|---|---|
| 정합성 | 단위 테스트 (2-6). 세분화↔모델 노드 1:1, parent 유효, 검색어 중복 없음 |
| 칩 2단계 | E2E — 상위 칩 클릭 시 세부 줄 등장, 세부 칩 클릭 시 검색어 이동, 새로고침 후에도 펼침 유지 |
| 3D 세분 | 실제 앱에서 허벅지 앞/뒤/종아리/전완에 hover 해 각각 다른 라벨이 뜨는지 확인 |
| 줌 | 실제 앱에서 휠·핀치 동작과 상하한 확인. 페이지 스크롤이 안 먹히는지도 함께 확인 |
| 회귀 | lint / tsc / unit / e2e / build 전부 |

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 세분 검색어의 YouTube 결과가 빈약할 수 있다 | 헬스장 용어로 잡되, 시드 후 결과 수를 실제로 확인한다. 3개 미만인 검색어는 상위 검색어로 되돌린다 |
| 모델 노드와 화면 데이터가 어긋나 회색 구멍이 생긴다 | 2-6 정합성 테스트로 빌드 단계에서 잡는다 |
| 휠 줌이 페이지 스크롤을 가로채 사용자가 갇힌다 | 캔버스 위에서만 가로챈다. 데스크톱에서는 왼쪽 레일이 좁아 빠져나갈 여백이 넓다 |
| 모델 용량 증가 | 근육 10개 추가 ≈ +60KB 예상. 681KB → 약 740KB. 삼각형 예산 합계는 7만으로 묶는다 |
| 상위 7개 동작이 바뀌어 기존 E2E 가 깨진다 | 상위 칩의 id·라벨·검색어·클릭 시 검색 동작을 그대로 둔다 |
